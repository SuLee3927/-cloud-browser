# Android Bridge · 模拟器与 USB 真机

这份配置把 Windows 已能看见的 Android 设备，经反向 SSH 隧道交给服务器上的 AI 工具。
默认脚本不开 Android；确认安全边界后再把 `home-bridge.cmd` 中的 `ENABLE_ANDROID` 改为 `1`。

## 1. 安装 ADB

安装 Android SDK Platform-Tools，打开 PowerShell：

```powershell
adb version
adb start-server
adb devices -l
```

若提示找不到 `adb`，把 `home-bridge.cmd` 的 `ADB_EXE` 改为 `adb.exe` 的完整路径。
代码块里的 `powershell` / `bat` 只是语言标签，不要复制进终端。

## 2A. 接模拟器

不同模拟器的 ADB 端口不同，先在模拟器设置里开启 ADB／开发者连接，再按厂商显示的端口连接：

```powershell
adb connect 127.0.0.1:模拟器端口
adb devices -l
```

看到 `127.0.0.1:端口 device` 才算成功。模拟器重启或 ADB server 重启后，可能需要重新 `adb connect`。

## 2B. 接 USB 真机

1. 在手机／平板开启开发者选项与 USB 调试。
2. 华为／HarmonyOS 还需开启“仅充电模式下允许 ADB 调试”（名称可能略有不同）。
3. USB 连接电脑；“USB 用途”保持仅充电也可以。
4. 设备弹出 RSA 调试授权时，核对自己的电脑并勾选“始终允许”。
5. 再运行：

```powershell
adb devices -l
```

状态必须是 `device`，不能是 `unauthorized` 或 `offline`。

## 3. 合并进后台启动器

编辑 `windows/home-bridge.cmd`：

```bat
set "ENABLE_ANDROID=1"
set "ADB_EXE=adb"
set "ADB_LOCAL_PORT=5037"
set "ADB_REMOTE_PORT=5039"
```

之后仍只需双击 `start-hidden.vbs`。它会在后台拉起 Chrome、启动本机 ADB server，并用同一条 SSH
连接转发 CDP 与 ADB。黑色调试窗口不必长期显示；后台的 `ssh.exe` 必须保持运行。

## 4. 服务器验证

```bash
ss -ltn | grep 5039
ADB_SERVER_SOCKET=tcp:127.0.0.1:5039 adb devices -l
```

第二条会列出 Windows ADB server 当前认识的设备。多设备时，每次命令都必须显式指定序列号：

```bash
ADB_SERVER_SOCKET=tcp:127.0.0.1:5039 adb -s '设备序列号' shell wm size
```

不要把真实序列号写入公开仓库；用服务器私有环境变量注入。

## 5. AI 工具层建议

### 设备路由

- 每个任务记住自己的设备，避免并发时模拟器／真机串台。
- 只有显式打开目标 App 时才切换设备；后续截图与点击沿用任务绑定。
- 一个真实账号最好绑定一台设备通道。

### 真机安全边界

- 为真机配置包名 allowlist，例如只允许目标通信 App。
- 文件发送只允许“任务档案 → 专属目录”，不要提供整个相册／文件系统枚举。
- 相册或系统文件选择器必须由目标 App 主动拉起；离开 allowlist 后拒绝继续点击。
- 不做自动轮询、自动群发或无人值守发送；由用户消息或明确任务触发。
- 支付、账号安全、设备管理等页面应直接拒绝操作。

### 中文输入

`adb shell input text` 不可靠地支持 Unicode。可选方案是安装开源 ADB 输入法，在一次输入期间临时切换，
输入后立即切回用户原来的输入法。不要永久替换用户键盘，也不要在公开配置里记录输入内容。

### 图片／文件桥

服务器生成的截图不在真机相册里。推荐只把用户明确点名的任务档案推入专属目录：

```bash
adb -s '设备序列号' shell mkdir -p /sdcard/Pictures/AiWorkspace
adb -s '设备序列号' push ./chosen.png /sdcard/Pictures/AiWorkspace/chosen.png
adb -s '设备序列号' shell am broadcast \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Pictures/AiWorkspace/chosen.png
```

普通文件可放 `/sdcard/Download/AiWorkspace/`。不要自动同步服务器目录，也不要反向扫描用户相册。

### 超时

真机文件经“服务器 → SSH → Windows ADB → USB”传输会比普通点击慢。建议仅把文件推送调用放宽到
120–180 秒；截图、点击、网页操作仍保持约 60 秒，避免所有动作长时间挂起。

### 元素树限制

某些 App 在真机上会向 `uiautomator dump` 返回空根节点，即使系统桌面能正常导出元素树。
这不是隧道故障。此时保留截图与 1:1 坐标点击；确有需要再添加 OCR，不要默认引入大组件。

## 6. 这套方案不负责“唤醒 AI”

ADB/MCP 只提供操作能力。若希望目标 App 一来消息就自动唤醒 AI，还需要：

```text
通知监听器／消息桥 → 常驻代理工作线程 → 模型调用 → ADB/MCP 操作真机
```

普通 ChatGPT 官端窗口不能被 MCP 反向唤醒。可使用 API 代理、Codex CLI 工作线程，或已有的实时消息桥。

## 排障

| 现象 | 检查 |
|---|---|
| 服务器没有 5039 | Windows 后台 SSH 未启动，或 `ENABLE_ANDROID` 仍为 0 |
| `adb devices` 为空 | Windows 本机先执行 `adb devices -l`；隧道不会替 ADB 发现设备 |
| `unauthorized` | 解锁真机并接受 RSA 调试授权 |
| 真机锁屏后点不动 | 解锁，并在测试期间延长自动锁屏时间 |
| 模拟器重启后消失 | Windows 再执行一次 `adb connect 127.0.0.1:端口` |
| 文件推送偶发超时 | 仅提高文件推送这条调用的超时，不要放宽全部操作 |
